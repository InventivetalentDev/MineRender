Version 2 · TypeScript rewrite

Interactive 3D Minecraft renders, anywhere.

MineRender turns Minecraft skins, blocks, items, entities, structures and worlds into interactive three.js scenes. V2 is a from-scratch TypeScript rewrite that runs in the browser and in Node, with a smarter asset pipeline and instanced rendering built for large scenes.

Get started See the examples npm
npm install minerender@alpha three

Looking for the original? MineRender V1 keeps working and stays online.

What's new in V2

Same goal as V1, rebuilt on a cleaner, faster foundation.

One renderer, every content type

A single Renderer owns a scene that mixes skins, blocks, items, entities and worlds. No more one-renderer-per-type wrappers.

Browser and Node

Separate browser and Node entry points behind one API. Load and merge assets, parse structures and build scenes server-side; headless rendering is in progress.

Renders only when needed

A dirty-flag render loop draws a frame only when something changed, plus an FPS cap. Idle scenes cost nothing.

Instanced by default

Identical models share a single InstancedMesh. Hundreds of blocks render in one draw call, which is the basis for world-scale scenes.

Layered asset sources

Stack resource-pack ZIPs, CDNs and custom namespaces in priority order. Per-key asset roots let one page mix game versions.

Current assets, cached

Defaults to Minecraft 1.21.11 assets, including the modern item definitions, with in-memory and persistent caches keyed by version.

Typed, tree-shakeable, side-effect free

Full TypeScript declarations, ESM and CJS builds, and no work at import time. Also available as a classic script-tag bundle.

Structures and worlds

Parse vanilla .nbt structures in the browser and place them into a chunked world. Region files and schematics are on the roadmap.

Examples

Each section renders only the example you select, and a viewport goes to sleep as soon as it scrolls out of view. That keeps the page light even with every feature on one page.

Getting started

Install from npm for bundlers and Node, or drop in the script-tag bundle.

Install

three.js is a peer dependency. V2 is published under the alpha dist-tag while the API settles.

npm install minerender@alpha three
# or
yarn add minerender@alpha three

Script tag

The bundle inlines three.js and exposes everything as window.MineRender.

<script src="https://unpkg.com/minerender@alpha/dist/bundle.js"></script>
<script>
    const renderer = new MineRender.Renderer({ controls: { enabled: true } });
    renderer.appendTo(document.getElementById("render"));
    renderer.start();
</script>

Your first render

Create a renderer, attach it to an element with a size, start the loop, then add content to its scene. Every add method is async because assets load on demand.

import { AssetKey, BlockStates, Renderer } from "minerender";

const renderer = new Renderer({
    camera: { position: [40, 30, 50], lookingAt: [0, 0, 0] },
    controls: { enabled: true }      // built-in OrbitControls
});
renderer.appendTo(document.getElementById("render")!);
renderer.start();

// A player skin
await renderer.scene.addSkin("https://textures.minecraft.net/texture/…");

// A block, from its blockstate
const state = await BlockStates.get(AssetKey.parse("blockstates", "grass_block"));
const block = await renderer.scene.addBlock(state!);
block.setPosition(block.getPosition().set(32, 0, 0));   // 1 block = 16 units

// Later
renderer.dispose();

Scene API

renderer.scene is a three.js Scene with asset-aware add methods.

scene.addSkin(textureUrl?, options?)   // SkinObject
scene.addBlock(blockState, options?)   // BlockObject
scene.addModel(model, options?)        // ModelObject | InstanceReference
scene.addEntity(entityModel, options?) // EntityObject | InstanceReference
scene.stats                            // object and instance counts

Scene objects extend Object3D and expose setPosition, setRotation, setScale, getGroupByName, getMeshByName, toggleGroupVisibility, removeFromScene and disposeAndRemoveAllChildren.

Object options

Every add method accepts the same base options.

{
    mergeMeshes: true,       // one geometry per model
    instanceMeshes: true,    // share an InstancedMesh per model
    maxInstanceCount: 50,    // slots per instanced model
    wireframe: false         // debug outlines
}

With instanceMeshes on, repeated models return an InstanceReference that only carries transforms. Pass instanceMeshes: false to get a standalone object you can remove individually.

The dirty flag

Frames are drawn only when something changed. Built-in controls and the scene's own add methods mark the scene dirty for you; anything you change by hand needs a nudge.

skin.getGroupByName("head")!.rotation.y = 0.5;
renderer.dirty = true;

// External event sources can request redraws too
renderer.registerEventDispatcher(myControls, "change");

Assets and caching

Assets are addressed by AssetKey and loaded through an ordered list of sources. The default source is the vanilla CDN at AssetLoader.ROOT.

import { AssetKey, AssetLoader, Caching, HostedAssetSource } from "minerender";

AssetLoader.addSource("pack", new HostedAssetSource("https://cdn.example/pack"));

AssetKey.parse("blockstates", "minecraft:oak_log");
new AssetKey("minecraft", "diamond_sword", "models", "item", "assets");

Caching.clear();          // in-memory caches
await Models.clearCache();

Lifecycle

stop() pauses the loop and start() resumes it. dispose() is final: it releases the WebGL context, controls and owned helpers.

renderer.stop();
renderer.start();
renderer.dispose();

// Node, or before unloading a page: end caches, queues and timers
import { shutdown } from "minerender";
shutdown();

Screenshots

Grab the current frame as a data URL. Render first so the drawing buffer is fresh.

renderer.renderer.render(renderer.scene, renderer.camera);
const dataUrl = renderer.toImage();

Node.js

The node export condition installs a Node environment provider backed by node-canvas and node-persist. Asset loading, model merging, atlas generation and structure parsing all work server-side today. Headless WebGL rendering is the next milestone on the roadmap. 

import { AssetKey, AssetLoader, AssetParser, Models, StructureParser, shutdown } from "minerender";

const sword = await Models.getMerged(new AssetKey("minecraft", "diamond_sword", "models", "item", "assets"));
console.log(sword?.elements?.length, "elements");

const nbt = await AssetLoader.get(new AssetKey("minecraft", "igloo/top", "structure", undefined, "data", ".nbt"), AssetParser.NBT);
const structure = await StructureParser.parse(nbt!);
console.log(structure.size, structure.blocks.length, "blocks");

shutdown(); // let the process exit

Performance notes

  • Use one renderer per visible area. Browsers limit WebGL contexts; this page keeps at most two alive and swaps the rest for snapshots.
  • Dispose what scrolls away. renderer.dispose() frees the context; recreate on demand. Assets stay cached, so the second load is quick.
  • Leave instancing on for repeated models. Set maxInstanceCount above the number of copies you expect.
  • Disable the composer (composer: { enabled: false }) when you do not need post-processing.
  • Lower fpsLimit on busy pages; the dirty flag already skips idle frames.
