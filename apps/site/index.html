Render Minecraft in the browser.

MineRender turns skins, blocks, items, entities, GUIs, structures and worlds into interactive three.js scenes. Version 2 is a TypeScript rewrite that also runs in Node, loads assets from any source, draws repeated models in a single call, and exports images and 3D models.

npm install minerender@beta three

What changed in version 2

The main differences from V1.

  • One renderer for every content type

    A single Renderer owns a scene that mixes skins, blocks, items, entities and worlds. V1's one-class-per-type wrappers and CombinedRender are gone.

    See the composed scene

  • Repeated models cost one draw call

    Identical models share an InstancedMesh, so a hundred stone blocks draw as one.

    See hundreds of blocks

  • Frames only when something changed

    A dirty-flag render loop skips idle frames entirely, with an optional FPS cap. Frame callbacks drive animation with time and delta while the loop runs.

    Redraws and animation

  • Browser and Node

    Separate entry points install the platform pieces for each side. Asset loading, model merging and structure parsing run in Node as well as in the browser.

    Using it in Node

  • Layered asset sources

    Stack resource-pack ZIPs, CDNs and custom namespaces in priority order. Each key can also carry its own asset root.

    Load a resource pack

  • Any game version

    Defaults to Minecraft 1.21.11, including the modern item definitions. Switch versions with one call; caches are keyed by version.

    Choosing a game version

  • Tints, UV lock and display poses

    Grass and leaves get their preview colors, rotated blockstates keep their texture orientation, and item models can take any of the game's display transforms.

    See display poses

  • Skin layouts are detected

    Classic, slim and legacy 64×32 skins are recognised from the texture. Every body part is addressable by name for toggles and poses.

    See skins

  • Entities from a versioned dataset

    Mob and block-entity geometry is extracted from each game version, with nested parts, texture variants, the render passes vanilla adds (charged creepers, spider eyes, dyed wool) and the keyframe animations of newer mobs.

    See entities

  • Capes in three layouts

    Vanilla, OptiFine and LabyMod cape textures attach to any skin, and capes.dev lookups resolve a player's cape by name or UUID.

    See capes

  • Fluids and animated textures

    Water and lava render with levels, slopes and flow. Waterlogged blocks include their water. mcmeta frame sequences animate.

    See water and lava

  • Worlds, not just structures

    Chunks with signed coordinates, face culling against opaque neighbors, and optional section meshing that merges static blocks into one mesh per 16³ section. Loads structure, schematic and Anvil region files.

    See structures and worlds

  • GUIs with items and recipes

    Inventory screens and HUD elements are built from cropped texture layers and item models in their GUI pose. Recipe JSON turns into crafting-table layers.

    See GUIs

  • Images and 3D exports

    Capture any frame as PNG or JPEG, optionally trimmed, or export the scene as glTF with textures, OBJ or PLY.

    See exports

  • Typed and tree-shakeable

    TypeScript declarations, ESM and CommonJS builds, no work at import time, and a classic script-tag bundle for pages without a build step.

    Install

Usage

What you need for most integrations. The generated API reference covers the rest.

Install

three.js is a peer dependency. V2 is published under the beta tag.

npm install minerender@beta three
# or
yarn add minerender@beta three

Without a build step, load the bundle. It includes three.js and exposes everything as window.MineRender.

<script src="https://unpkg.com/minerender@beta/dist/bundle.js"></script>
<script>
    const renderer = new MineRender.Renderer({ controls: { enabled: true } });
    renderer.appendTo(document.getElementById("render"));
    renderer.start();
</script>

Your first render

Create a renderer, attach it to an element that has a size, start the loop, then add content to its scene. Every add method is asynchronous because assets load on demand.

import { AssetKey, BlockStates, Renderer } from "minerender";

const renderer = new Renderer({
    camera: { position: [40, 30, 50], lookingAt: [0, 0, 0] },
    controls: { enabled: true }   // built-in orbit controls
});
renderer.appendTo(document.getElementById("render")!);
renderer.start();

// A player skin
await renderer.scene.addSkin("https://example.com/skin.png");

// A block, from its blockstate
const state = await BlockStates.get(AssetKey.parse("blockstates", "grass_block"));
const block = await renderer.scene.addBlock(state!);
block.setPosition(block.getPosition().set(32, 0, 0));   // 1 block = 16 units

// When the view goes away
renderer.dispose();

Scene and objects

renderer.scene is a three.js Scene with asset-aware add methods.

scene.addSkin(textureUrl?, options?)    // SkinObject
scene.addBlock(blockState, options?)    // BlockObject
scene.addModel(model, options?)         // ModelObject | InstanceReference
scene.addEntity(entityModel, options?)  // EntityObject | InstanceReference
scene.addGui(layers, options?)          // GuiObject
scene.stats                             // object and instance counts

Scene objects extend Object3D. Beyond the usual three.js properties they offer setPosition, setRotation, setScale, getGroupByName, getMeshByName, toggleGroupVisibility, removeFromScene and dispose. Skins add setSkinTexture, setSlim and setCapeTexture; blocks add setState; entities add getLayerGroup.

Every add method accepts the same base options, plus type-specific ones.

{
    mergeMeshes: true,        // one geometry per model
    instanceMeshes: true,     // share an InstancedMesh per model
    maxInstanceCount: 50,     // slots per instanced model
    wireframe: false,         // debug outlines

    // models and blocks
    displayPosition: DisplayPosition.GUI,   // apply a display transform
    tints: { 0: 0x79c05a },                 // sRGB color per tint index

    // skins
    slim: undefined,          // true, false, or undefined to detect
    legacy: undefined,        // 64×32 layout; undefined to detect

    // entities
    tints: { wool_color: 0xf9801d },   // colors for the dataset's tint labels
    flip: undefined           // true forces vanilla's plain flip, false keeps raw model space
}

With instanceMeshes on, repeated models return an InstanceReference that only carries transforms. Its dispose() frees the slot for reuse. Pass instanceMeshes: false for a standalone object.

Blocks whose model has no geometry in the game (chests, beds, skulls, signs, banners, shulker boxes) are drawn through the entity models the dataset maps them to, rotated by their blockstate properties. block.blockEntities holds those objects.

Entity models draw main plus the passes the dataset lists for them. Passes with a condition are enabled through when; tint labels take colors through tints. An explicit layers list draws exactly those geometry layers instead.

const key = new BasicAssetKey("minecraft", "sheep");
await Entities.getPassList(key);   // [{ layer: "wool", when: "not_sheared", tint: "wool_color" }, ...]

const model = await Entities.getEntity(key, undefined, { when: ["not_sheared"] });
const sheep = await scene.addEntity(model!, { tints: { wool_color: 0xf9801d } });
sheep.getLayerGroup("wool")!.visible = false;   // every layer is a group

Mobs with keyframe animations (warden, frog, camel, breeze, armadillo, sniffer, bat and others) expose them through Entities.getAnimations. The entity owns no clock, so advance it from a frame callback.

const animations = await Entities.getAnimations(key);   // undefined without any
warden.playAnimation(animations!.roar, { loop: true, speed: 1 });
const stop = renderer.onFrame(({ delta }) => warden.advanceAnimation(delta));
warden.setAnimationTime(1.5);   // or pose at an explicit time
warden.stopAnimation();         // restores the default pose

GUIs take ordered layers in GUI pixels, with y growing down: texture crops, or item models in their GUI display pose. gui.bounds reports the drawn area for fitting an orthographic camera, GuiHelper.inventorySlot turns a slot index into a position, and GuiHelper.recipe lays out a crafting recipe.

const gui = await scene.addGui([
    { texture: "minecraft:gui/container/generic_54", crop: [0, 0, 176, 222] },
    { item: "minecraft:item/apple", position: GuiHelper.inventorySlot(0, [8, 18]) },
    { item: "minecraft:item/grass_block", position: GuiHelper.inventorySlot(1, [8, 18]), tints: { 0: 0x91bd59 } }
]);

const table = await scene.addGui(GuiHelper.recipe(recipeJson, {
    resolveIngredient: () => "minecraft:diamond"   // concrete item for tags and alternatives
}));

Redraws and animation

Frames are drawn only when something changed. The built-in controls and the scene's add methods mark the scene dirty. Set renderer.dirty after other changes.

skin.getGroupByName("head")!.rotation.y = 0.5;
renderer.dirty = true;

// Other event sources can request redraws too
renderer.registerEventDispatcher(myControls, "change");

For continuous motion, subscribe to frames. Callbacks run before each draw while the loop is started, respect fpsLimit, pause with stop() and keep the scene drawing without dirty flags. Both values are seconds.

const head = skin.getGroupByName("head")!;
const unsubscribe = renderer.onFrame(({ time, delta }) => {
    head.rotation.y = Math.sin(time) * 0.5;
});
unsubscribe();   // when done; dispose() clears all callbacks

Assets and versions

Assets are addressed by AssetKey and loaded through an ordered list of sources. The default source is a CDN with vanilla assets for the version in AssetLoader.ROOT.

import { AssetKey, AssetLoader, Caching, HostedAssetSource, Models } from "minerender";

// Keys
AssetKey.parse("blockstates", "minecraft:oak_log");
new AssetKey("minecraft", "diamond_sword", "models", "item", "assets");

// Another game version for everything that follows
AssetLoader.setVersion("1.20.4");

// Sources added later are searched first
AssetLoader.addSource("pack", new HostedAssetSource("https://cdn.example/pack"));

// In-memory caches
Caching.clear();
await Models.clearCache();

Resource-pack ZIPs work in the browser through BrowserArchiveProxy and ArchiveAssetSource; see the example. Persistent caches (IndexedDB in browsers, a directory in Node) are keyed by asset root, so versions never collide.

Worlds and files

MineRenderWorld stores blocks in 16³ chunks with signed coordinates and keeps faces against opaque neighbors from being drawn. With sectionMeshing, static opaque cubes are merged into one mesh and atlas per section; everything else stays an individual object.

import { AnvilParser, MineRenderWorld, NBTHelper, SchematicParser, StructureParser } from "minerender";

const world = new MineRenderWorld(renderer.scene, { sectionMeshing: true });

// Blocks from code
await world.setBlockAt(0, 0, 0, { type: "minecraft:stone" });
await world.setBlockAt(0, 1, 0, { type: "minecraft:oak_fence", state: { north: "true" } });

// Vanilla structure files and legacy schematics
const nbt = await NBTHelper.fromBuffer(bytes);
await world.placeMultiBlock(await StructureParser.parse(nbt));
await world.placeMultiBlock(await SchematicParser.parse(nbt));

// Java region files (1.13+): list the stored chunks, then place one at its world position
const chunks = AnvilParser.getChunkList(regionBytes);
const chunk = await AnvilParser.parseChunk(regionBytes, chunks[0].x, chunks[0].z);
await world.placeChunk(chunk!);

await world.clear();

Placement is batched through a BatchedExecutor so the page stays responsive. The world has no lighting, biome colors or level of detail.

Exporting

toImage renders a fresh frame and returns a data URL. SceneExporter writes the visible meshes with their instance placements.

import { SceneExporter } from "minerender";

const png = renderer.toImage();                          // full canvas
const jpeg = renderer.toImage(true, "image/jpeg", 0.9);   // trimmed to the drawn pixels

const glb = await SceneExporter.toGLTF(renderer.scene, { binary: true });   // textures and tints kept
const obj = SceneExporter.toObj(renderer.scene);                           // geometry only
const ply = SceneExporter.toPLY(skin);                                     // any Object3D as the root

glTF export needs a browser. Custom shading is not baked into the exported materials.

Lifecycle

stop() pauses the loop and start() resumes it. dispose() is final: it releases the WebGL context, the controls and owned helpers. Shared assets stay cached.

renderer.stop();
renderer.start();
renderer.dispose();

// In Node, or before unloading a page: end caches, queues and timers
import { shutdown } from "minerender";
shutdown();

Node

The node export condition installs a platform provider backed by node-canvas and node-persist. Asset loading, model merging, atlas generation and structure parsing work in Node. The Node entry does not create a WebGL context, so drawing to an image there needs one from a package such as headless-gl. 

import { AssetKey, AssetLoader, AssetParser, Models, StructureParser, shutdown } from "minerender";

const sword = await Models.getMerged(new AssetKey("minecraft", "diamond_sword", "models", "item", "assets"));
console.log(sword?.elements?.length, "elements");

const key = new AssetKey("minecraft", "igloo/top", "structure", undefined, "data", ".nbt");
const structure = await StructureParser.parse((await AssetLoader.get(key, AssetParser.NBT))!);
console.log(structure.size, structure.blocks.length, "blocks");

shutdown(); // let the process exit

Performance

  • One renderer per visible area. Browsers limit WebGL contexts. This page keeps at most two alive and swaps the rest for snapshots.
  • Dispose what scrolls away and recreate it on demand. Assets stay cached, so the second load is quick.
  • Leave instancing on for repeated models, and set maxInstanceCount above the number of copies you expect.
  • Turn on sectionMeshing for worlds and large structures. Static blocks become one mesh per section.
  • Disable the composer when you do not need post-processing, and keep pixelRatio at 1 unless you need sharper output.
  • Lower fpsLimit on busy pages. The dirty flag already skips idle frames.

A skin viewer

V1 
const skinRender = new SkinRender({
    controls: { enabled: true }
}, document.getElementById("skin"));
skinRender.render("inventivetalent");
V2 
const renderer = new Renderer({ controls: { enabled: true } });
renderer.appendTo(document.getElementById("skin")!);
renderer.start();

const skin = await renderer.scene.addSkin();
const texture = await Skins.fromUuidOrUsername("inventivetalent");
if (texture) await skin.setSkinTexture(texture);

Animating a part

V1 
element.addEventListener("skinRender", event => {
    const head = event.detail.playerModel.getObjectByName("head");
    head.rotation.y += 0.01;
});
V2 
const head = skin.getGroupByName("head")!;
renderer.onFrame(({ delta }) => {
    head.rotation.y += delta;     // radians per second
});
